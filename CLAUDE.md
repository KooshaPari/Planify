## Branch & Commit Discipline

- Branch from `main` for all work: `feat/`, `fix/`, `chore/`, `docs/`, `refactor/`
- Conventional Commits required
- Never commit directly to `main`
- Never modify `upstream/` — customizations land outside (`site/`, `infra/`, `docs/adr/`)
- To sync from upstream: see `AGENTS.md` "Upstream Sync" section

## Security

- See `SECURITY.md` for reporting channels (security@phenotype.space).
- Do not commit `.env`, `apps/api/.env`, or any plaintext secrets.
- Django SECRET_KEY is generated by `upstream/setup.sh` (uses `secrets.token_urlsafe(50)`).
- Production deployments MUST override `PLANE_POSTGRES_PASSWORD` and `PLANE_SECRET_KEY` env vars.

## Bead / Proc discipline

All non-trivial work MUST be tracked as beads:
```bash
./beads/bead-ctl.sh claim <target> "<text>"
./beads/bead-ctl.sh complete <target> "<text>"
./beads/bead-ctl.sh warn <target> "<text>"
./beads/bead-ctl.sh goal <target> "<text>"
./beads/bead-ctl.sh intent <target> "<text>"
```

Reference bead IDs in PR descriptions.
